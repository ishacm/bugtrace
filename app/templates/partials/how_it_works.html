How it works technically
Bug source
Cases are SWE-bench Verified instances. The agent receives only the issue text, the repository name and the base commit (PublicCase). The reference patch, test patch and FAIL_TO_PASS/PASS_TO_PASS lists stay evaluator-only.
Agent
One LangGraph state graph: understand issue → plan → search → inspect → hypothesis → verify evidence (bounded loop) → root cause → propose patch → interrupt for approval → apply. Default limits are 4 iterations, 30 tool calls and 2 patch attempts.
Repository checks
The model has no shell. A read-only MCP server exposes list_directory, read_file, search_code, find_symbol, list_test_files, git_log, git_show, git_diff and check_patch, scoped to one per-investigation git clone. Each result gets a deterministic evidence ID.
Grounding
Claims citing no known evidence ID are dropped. Suspects on paths no tool returned are rejected. Confidence (LOW/MEDIUM/HIGH) follows explicit evidence rules.
Approval and patching
Diffs are strictly validated and checked with git apply --check. A separate MCP server applies only the diff whose sha256 matches the recorded approval. Nothing is committed or pushed.
Evaluation
The service, not the agent, runs the pinned official SWE-bench harness in Docker. RESOLVED comes only from the harness's own verdict. Benchmark evaluation runs only in a local or manual evaluation environment.
